# HA Beacon

Третий аддон семейства: **маячок состояния дома** + **пульт отопления**.

Раз в N минут (по умолчанию 10) отправляет компактный JSON на домен
(`https://virvinsky.ru/ha/beacon.json`) по FTP — **напрямую**, не через VPS-релей.
Поэтому даже если `ha_link`/VPS недоступны, файл продолжает обновляться, а
приложение может показать: малина жива, что с температурой и автоматикой.

С версии **0.2.0** аддон ещё и принимает команды: раз в минуту смотрит файл
`command.json` в том же каталоге, применяет режимы отопления и **удаляет файл**,
чтобы команда не перезаписывала систему бесконечно.

## Что публикуется

Короткий JSON (несколько сотен байт):

```json
{"schema":1,"ts":"2026-11-23T15:00:00Z","up":3600,"ha":"2026.8.3",
 "t":{"d01":8.9,"g01":10.6,"b01":4.9,"b02":4.8,"b03":6.9},
 "on":{"r05":0,"roz":0,"b1":0,"b2":0,"b3":0,"r06":0},
 "m":{"d":1,"n":0,"p":0,"k":1,"b1":0,"bp":0},
 "z":{"house":"day","boiler":"day","bath1":"off","bath2":"night"},
 "b":{"b01":21,"b02":88,"b03":5},
 "p":{"r05":0},"r":1,
 "c":["b03:5%"]}
```

- `t` — температуры (дом, котельная, баня 1/2/подвал);
- `on` — состояния розеток/реле;
- `m` — старые флаги автоматизаций (для совместимости);
- `z` — текущий режим каждой зоны: `day` / `night` / `prog` / `off`;
- `b` — заряд батарей, `p` — мощность котла;
- `r` — 1/0: доступен ли релей (до трёх проб `https://ha.virvinsky.ru:8443/api/`;
  туннель иногда переподключается на пару секунд, поэтому одна проба даёт ложные
  «недоступен»);
- `c` — важное (низкий заряд, нет данных, нет розжига);
- `a` — состояния аддонов `ha_link` и `ha_control` (если Supervisor разрешает
  чтение `/addons`; при `hassio_role: default` может отсутствовать).

## Пульт (удалённое управление)

Интерфейс — `https://virvinsky.ru/ha/control.php` (пароль) или панель
«Маячок дома» в приложении. Оба пишут файл:

```json
{"schema":1,"id":"20261124T091500Z-ab12cd34","ts":"2026-11-24T09:15:00Z",
 "source":"control.php",
 "set":{"house":"prog","boiler":"day","bath1":"off","bath2":"night"}}
```

Правила:

- зоны: `house`, `boiler`, `bath1`, `bath2`;
- режимы: `day` (день-ночь по датчику), `night` (постоянно ночью),
  `prog` (до заданной t), `off` (отключено);
- аддон **сначала выключает** остальные режимы зоны, потом включает выбранный;
- после применения пишет `command_result.json` (`ok`, `applied`, `errors`)
  и **удаляет** `command.json`;
- повторно один и тот же `id` не применяется (защита, если файл не удалился);
- список сущностей жёстко ограничен автоматиками отопления — произвольные
  сервисы через файл вызвать нельзя.

## Настройки

| Опция | Смысл |
|---|---|
| `interval_minutes` | интервал публикации (1–60, по умолчанию 10) |
| `command_poll_seconds` | как часто проверять `command.json` (20–600, по умолчанию 60) |
| `ftp_host` | `vh330.timeweb.ru` |
| `ftp_user`, `ftp_pass` | доступ к хостингу |
| `ftp_path` | `public_html/ha` |
| `public_url` | адрес файла для приложения |

## Устойчивость

- `boot: auto` — стартует после ночной перезагрузки HA;
- `watchdog: http://[HOST]:[PORT:8097]/health` — Supervisor перезапустит аддон,
  если публикаций нет дольше `max(3 интервала, 30 минут)`;
- `run.sh` перезапускает `beacon.py`, если тот упал;
- сетевые ошибки не роняют процесс: следующая попытка через минуту;
- ошибка команды не роняет аддон: пишется в `command_result.json` и в лог.

## Сборка

Образ: `ghcr.io/healtrap/ha-link-addon/ha_beacon-{arch}`.
Собирается GitHub Actions из `addons/ha_beacon` (workflow `build-beacon.yml`).

## Права

- `homeassistant_api: true` — читать `/core/api/states` и `/core/api/config`,
  вызывать `automation.turn_on` / `automation.turn_off`;
- `hassio_api: true`, `hassio_role: default` — смотреть состояния аддонов
  `ha_link`/`ha_control`;
- FTP-доступ к хостингу задаётся опциями (логин/пароль), ничего не хранится
  в образе.

## Файлы на хостинге

- `control.php` — пульт для браузера, лежит в `public_html/ha` на хостинге.
  Исходник: `host/control.php` в корне репозитория (в аддон-зеркало не
  попадает — там только код аддона).
